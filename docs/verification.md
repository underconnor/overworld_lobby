실제 Paper의 PluginManager에 이벤트를 전달해 다음 결과를 확인했다.

- 자연 생성·스포너 생성 이벤트를 차단한다. Paper의 실제 `spawnEntity(..., NATURAL)` 호출로 생성한 엔티티도 월드에 추가되지 않는다. `CUSTOM` 생성은 허용한다.
- 물 흐름, 성장, 피스톤, 폭발을 차단하고 레드스톤 출력을 유지한다.
- 기본 시간을 6000으로, 날씨를 맑음으로 고정한다. 설정 재적용으로 18000·천둥을 적용하며, 잘못된 설정은 기존 동작을 유지한다.
- 설정 비활성화 시 블록 보호를 해제하고 기존 시간 진행·날씨 진행·자연 스폰 게임 규칙을 복원한다. 월드 목록에 따른 적용 범위도 검사했다.
- 시간이 이미 고정된 네더·엔드에서도 플러그인이 활성 상태를 유지하고 블록 보호와 자연 스폰 차단을 적용한다.
- `/lobby fly on`은 서바이벌에서 비행 허용과 비행 상태를 켠다. `off`는 비행을 끄며, 비행이 꺼진 상태의 비행 시작 이벤트를 차단한다.
- `protection.hunger`와 `players.keep-food-full`이 켜진 보호 월드에서는 일반 사용자·OP·전체 우회·개별 권한 사용자 모두 음식 20·포만감 20·피로도 0을 유지한다. 기존 배고픔 우회 노드를 부여해도 해제되지 않는다. 음식 유지 또는 배고픔 보호를 끄거나 보호 범위를 벗어나면 기존 수치를 복원하고, 다시 활성화하면 가득 채운다.
- `protection.player-damage`가 켜진 보호 월드의 낙하 피해는 OP·전체 우회·개별 플레이어 피해 우회 여부와 관계없이 차단한다. 화염·익사 등 다른 피해와 PvP에는 기존 동작별 권한 우회를 유지한다. 피해 보호를 끄거나 보호 범위를 벗어나면 낙하 차단도 해제된다.

## Citizens NPC 클릭

Citizens가 활성 상태에서 직접 등록한 `NPC` 메타데이터(Boolean.TRUE, owner 이름 Citizens)가 있는 엔티티의 두 우클릭 이벤트는 로비 조작 보호를 건너뛴다. NPC 클릭에는 `여기서는 이 엔티티를 조작할 수 없습니다.` 안내를 표시하지 않는다. 일반 엔티티 조작과 NPC 공격·갑옷거치대 물리 변경은 기존 규칙을 유지하며, 다른 플러그인이 취소한 이벤트를 풀지 않는다.

실제 Paper·Citizens 플러그인 소유 메타데이터로 양손·두 클릭 종류의 로비 통과와 안내 부재, 일반 엔티티 차단·안내, 공격 보호와 기존 취소 상태 유지를 확인했다. 실제 Citizens registry에서 만든 NPC의 공식 메타데이터와 클릭 안내 부재도 확인했다. 다른 플러그인 소유·거짓 값·비활성 소유 플러그인·문자열 표식은 NPC 예외를 받지 않는다. Citizens API를 빌드 의존성으로 추가하지 않았으며 Citizens가 없는 환경의 회귀 테스트도 통과했다.

이 검증은 실제 클라이언트 클릭과 운영 NPC command trait의 실행을 포함하지 않는다.

## 월드별 시간·날씨 명령

`/lobby time <day|night|noon|midnight|0..23999|off|default> [world]`와 `/lobby weather <clear|rain|thunder|off|default> [world]`를 실제 Paper 명령 처리기로 실행했다.

- 이름에 점을 포함한 두 번째 실제 월드를 만들고, 첫 월드와 독립적인 시간·날씨 설정을 적용했다. 시간만 수정해도 같은 월드의 날씨와 다른 월드의 설정을 유지했다.
- OP와 `overworld.lobby.admin` 사용자는 허용했다. 일반 사용자와 전체 개인 우회 권한만 가진 사용자는 관리 명령을 거부했다. 현재 월드 기본 선택, 콘솔의 명시적 월드 필수, 값·보호 월드 이름 자동 완성을 검사했다.
- 숫자·별칭과 rain/thunder/clear를 즉시 적용했다. `off`는 해당 기능의 원래 전체 시간·날씨 상태·지속시간·진행 규칙을 복원했고, `default`는 선택한 기능의 예외만 지워 기존 공통 설정을 다시 적용했다.
- 잘못된 값, 없는 월드와 보호 범위 밖의 월드는 파일을 변경하지 않았다. 네더·엔드 시간/날씨 고정은 거부하고 `off`·`default`는 허용했다. 고정 시간의 사용자 정의 NORMAL 월드에서는 날씨를 설정할 수 있다.
- 점이 포함된 월드 이름이 YAML에서 다른 경로로 나뉘지 않았고, 실제 전체 재시작 후 각 월드의 저장한 설정을 다시 적용했다. 기존 공통 설정만 있는 파일도 계속 적용했다.

자동 테스트에서는 저장 실패와 적용 실패 후 원본 바이트·설정 복원, UTF-8·주석·파일 권한 보존, 다른 설정과 월드 보존을 추가로 확인했다.

## 정확한 스폰과 자동 이동

초기 자동 이동 목적지가 `x=-4.5, y=63.5, z=-1.5, yaw=180, pitch=0`과 정확히 일치한다. 소수점 위치를 유지하며 기존 정수 단위 월드 스폰을 수정하지 않는다. 수동 `/spawn` 명령은 1.0.6에서 등록을 제거했다.

- 실제 Bukkit 명령 맵에서 `/spawn`과 `/overworldlobby:spawn`이 없고 실행되지 않는 것을 확인했다. 일반 사용자·OP·전체 우회 사용자와 기존 `overworld.lobby.spawn` 권한을 부여한 사용자 모두 수동 이동이 불가능하다. 전용 권한 선언도 제거했다.
- 실제 PluginManager에 `PlayerJoinEvent`를 전달한 뒤 다음 틱의 공통 스폰 이동을 확인했다.
- `PlayerRespawnEvent`의 목적지와 공허 아래로 내려가는 `PlayerMoveEvent`의 이동 목적지가 정확한 스폰으로 변경된다. 공허 복구는 누적 낙하 거리를 0으로 초기화한다.
- OP과 전체 우회 사용자도 정확한 자동 접속 이동·리스폰·공허 복구를 적용한다. 기존 `overworld.lobby.bypass.spawn` 권한을 명시적으로 부여하거나 접속 이벤트 직후 새로 부여해도 공통 이동이 유지된다. 해당 권한 선언은 플러그인에서 제거됐다.
- 접속·리스폰·공허 복구 설정을 각각 끌 수 있다. 보호 범위 밖의 출발 월드에는 자동 이동을 적용하지 않는다. 수동 명령 제거 후에도 기존 자동 이동과 설정별 동작은 유지된다.
- 설정에 지정한 목적지 월드를 찾을 수 없으면 이동하지 않는다. 명시적으로 지정한 로드된 월드와 빈 월드 설정의 기본 선택도 검사했다.

`/setspawn`과 `/lobby setspawn`을 실제 등록된 명령 처리기로 실행했다. OP 또는 `overworld.lobby.admin`은 현재 위치·시선이나 명시한 월드·소수 좌표를 저장할 수 있으며, 일반 사용자와 전체 우회 권한만 있는 사용자는 거부한다. 저장 직후 자동 이동에 새 목적지가 적용되며 다른 개인·월드 설정과 자동 이동 옵션을 유지한다. 잘못된 좌표·시선·월드는 파일을 변경하지 않는다. 전체 재시작 후 변경한 `39.75, 72.125, -18.5`, 시선 `-135.5, 24.25`를 다시 확인했다. Minecraft·Multiverse의 월드 스폰은 변경하지 않았다.

## 보이지 않는 월드별 사각 경계

두 코너의 X/Z 좌표로 `/lobby border set`을 실행하고, `pos1`·`pos2` 선택·`info`·`off`와 잘못된 입력 처리를 검사했다. 월드마다 별도 사각형을 저장하며 경계선은 포함하고 모든 Y 높이에 적용한다. 기본 설정에 경계가 없는 월드는 제한하지 않는다.

- 실제 Paper 이동·텔레포트 이벤트에서 경계 밖 이동을 막았다. 일반 사용자뿐 아니라 OP·전체 우회·기존 개별 경계 우회 노드 사용자도 같은 경계를 적용한다. 경계 우회 권한 선언은 제공하지 않는다.
- 경계 밖에서 안으로 돌아오는 이동은 허용한다. 이미 밖에 있거나 설정 변경으로 밖에 놓인 플레이어의 복구 경로를 검사했으며, 설정 변경 시 안에 있는 사용자는 공통 스폰으로 이동시키지 않는다. 탑승 이동·포털 처리와 보호 범위·설정 해제는 자동 테스트로 추가 확인했다.
- 거부 안내는 빨간색 `이 월드의 경계를 벗어날 수 없습니다.`이며 `[로비]` 접두어가 없다. 기존 플레이어별 안내 간격을 공유하고, 안내 생략 중에도 이동을 차단한다.
- 경계 해제 시 바깥 텔레포트를 허용하고, 전체 재시작 후 저장한 사각형과 차단을 다시 적용한다. 실제 Minecraft 월드 경계 크기는 변경하지 않았으며 벽·파티클·블록을 생성하지 않는다.

이 확인은 실제 Paper 월드와 이벤트에 합성 플레이어를 사용했다. 실제 클라이언트 이동 패킷·화면 표시를 검증한 결과는 아니다.

## LuckPerms 권한 검사

실제로 로드된 LuckPerms의 사용자 데이터와 `LuckPermsPermissible`을 사용했다. 테스트용 CraftPlayer의 네이티브 권한 필드에도 해당 객체를 연결하고 `hasPermission` 호출을 전달하여 플러그인의 일반 권한 검사와 접속 이벤트의 LuckPerms 컨텍스트 처리를 확인했다.

- 권한 없는 사용자 차단, `bypass.block-break` 및 `bypass.interact`의 동작별 허용, 행동 제한 전체 `overworld.lobby.bypass` 허용을 검사했다.
- PvP·상자에 대한 개별 우회도 확인했다. 배고픔과 경계는 권한으로 우회하지 않으며, 개별 PvP 권한은 낙하 피해 보호를 해제하지 않는다.
- 권한을 회수하면 플러그인 설정 재적용 없이 다음 이벤트부터 차단한다.
- 플레이어 전체 우회 권한이 있어도 행위자 없는 월드 변화 차단은 환경 설정을 따른다.
- LuckPerms 권한을 저장한 뒤 서버 재시작을 거쳐 블록 파괴 권한이 유지되고, 문 차단과 상자 허용은 계속 적용된다.

OP 상태를 LuckPerms Bukkit의 실제 권한 컨텍스트에 반영해 기본 권한과 전체 우회를 검사했다. 등록된 전체 우회 권한의 하위 노드도 실제 LuckPerms 권한 계산에 반영됐다. LuckPerms에서 `overworld.lobby.bypass=false`를 명시해 노드 조회가 거부되더라도 네이티브 `isOp()`가 참이면 전체 우회가 적용된다.

OP과 전체 우회 권한을 가진 일반 사용자에게 블록 파괴·설치, 문과 설정으로 잠근 상자, 양동이, 엔티티 조작·공격, PvP, 아이템 사용·버리기·줍기, 탈것, 포털과 낙하 이외의 피해를 허용했다. 음식·포만감 유지, 낙하 피해 차단과 활성화된 월드 경계는 우회하지 않는다. OP 해제 또는 일반 사용자의 전체 우회 권한 회수 후에는 일반 행동 보호와 서바이벌·비행 설정이 다시 적용됐다. 기존 배고픔 우회 노드와 개별 플레이어 피해 우회도 공통 음식·낙하 보호를 해제하지 않는다.

## 접속 시 크리에이티브와 자유로운 게임 모드·비행

- OP과 전체 우회 사용자는 공통 스폰 이동 이후 크리에이티브 기본값을 받는다. LuckPerms에서 전체 우회 노드를 명시적으로 거부한 OP도 같은 결과를 확인했다.
- 이후 크리에이티브·서바이벌·관전 모드 변경 이벤트를 허용했다. 접속 기본값이 적용된 뒤 직접 선택한 게임 모드는 다음 틱과 실제 플레이어 관리 재점검 이후에도 유지됐다.
- OP과 전체 우회 사용자가 직접 서바이벌을 선택하면 `players.allow-flight: false`와 명시적인 `overworld.lobby.fly=false` 상태에서도 `/lobby fly on/off`가 작동한다. 관리 재점검도 선택한 비행 상태를 유지한다. 크리에이티브·관전 모드에서 `off`는 실제 비행을 끄면서 기본 비행 능력을 유지한다.
- 접속 후 지연된 크리에이티브 기본값이 실행되기 전에 전체 우회 권한을 회수하면 재확인한 일반 보호·서바이벌 설정을 덮어쓰지 않는다. 일반 사용자는 설정된 서바이벌·비행·음식 유지가 적용되며 임의 크리에이티브 변경은 차단된다.

## 읽기 전용 상태 명령

`/lobby status`의 콘솔·관리 권한·OP 호출과 일반 사용자 거부를 확인했다. 격리 서버의 실제 접속자 목록은 비어 있으며 `online=0 op=0 permission-bypass=0 effective-bypass=0 creative=0 survival=0` 집계가 일치했다. 일반 사용자에게는 집계를 공개하지 않고 자동 완성에서도 명령을 제외한다. 합성 플레이어는 실제 접속자 목록에 넣지 않았다. 접속자가 있는 운영 집계는 아래 버전별 운영 적용 절에서 구분했다.

## 차단 안내와 설정 재적용

- 차단된 블록 파괴에는 빨간색 `여기서는 블록을 부술 수 없습니다.`를, 문 사용에는 `여기서는 이 블록을 사용할 수 없습니다.`를 표시한다. `[로비]` 표시는 없다.
- 같은 플레이어가 연속으로 다른 행동을 시도해도 안내 횟수를 제한한다. 안내가 생략되는 동안에도 실제 행동은 계속 차단된다. 기본 간격은 1000ms이다.
- 허용된 상자 열기, 개별 우회 권한 및 OP으로 허용된 행동에는 차단 안내가 없다. 상자를 열면서 들고 있는 양동이 사용이 제한되더라도 상자 접근 실패로 안내하지 않는다.
- 음식 유지와 환경 피해 방지는 안내를 보내지 않는다. 안내 전체 끄기, 행동별 빈 문구, 채팅·액션바 선택과 사용자 문구 재적용을 확인했다.
- 잘못된 안내 간격이나 문자열이 아닌 접두어를 재적용하면 기존 안내 문구·블록 보호·시간·플레이어 설정을 유지한다. 안내 설정 실패로 다른 설정이 일부만 적용되지 않는다.

## 1.0.2 릴리즈와 운영 적용

2026-10-03 KST에 [v1.0.2 릴리즈](https://github.com/underconnor/overworld_lobby/releases/tag/v1.0.2)를 게시했다. [Build](https://github.com/underconnor/overworld_lobby/actions/runs/37114434315)와 [Release](https://github.com/underconnor/overworld_lobby/actions/runs/37114447809)가 [커밋 59e7d443](https://github.com/underconnor/overworld_lobby/commit/59e7d443832486a63df1ebe62656f9d41ed23e5a)에서 성공했다. 공개 JAR는 66,246바이트이며, 내려받은 릴리즈·격리 Paper 검증·운영 설치 파일의 SHA-256이 모두 `2f9f92f6026ac85251af492e8a9b6316d88d55be77de941a4ea1d0f5aa824827`로 일치했다.

로비를 정상 종료하고 217,475,557바이트 백업을 만든 뒤 로비에만 적용했다. 백업 SHA-256은 `451ee10bcf90bd210fdfd9a7f88117ad12bdac28d39e2c701885d63281d3dc56`이다. 기존 설치 경로의 JAR를 교체했고 기존 로비 설정과 Multiverse 설정은 보존됐다.

별도 읽기 전용 재점검의 28개 항목이 모두 통과했다.

- OverworldLobby 1.0.2를 포함한 로비 플러그인 7개가 로드됐으며 점검 대상 서비스 7개가 정상 상태였다. 기동 호환성·작업·이벤트 예외와 플러그인 비활성화는 없었다.
- 실제 운영 `/lobby status` 응답은 `OverworldLobby 1.0.2 online=1 op=1 permission-bypass=1 effective-bypass=1 creative=1 survival=0`이었다. 실제 접속자 1명의 서버 OP 상태·전체 우회 노드·유효 우회와 크리에이티브 상태를 확인했다.
- 설치된 전체 우회 권한의 하위 노드, 승인된 차단 안내, 일반 사용자용 서바이벌·비행·음식·피해 보호 설정을 확인했다. 정확한 공통 스폰과 접속·리스폰 이동·공허 복구 설정도 유지됐다. 실제 월드 시간 6000틱과 자연 스폰·시간 진행·날씨 진행 고정을 확인했다.
- 기존 월드 식별 정보, 컨테이너 이미지·마운트·Compose 구성, 접속 정책·OP·화이트리스트, 기존 플러그인 JAR, LuckPerms 설정과 로비 외 컨테이너 7개의 상태가 보존됐다. 배포 대상에 LuckPerms 저장소 변경은 포함하지 않았다.

운영 접속자의 권한·역할·게임 모드를 점검 명령으로 변경하지 않고 서버 상태를 읽어 확인했다. 실제 클라이언트에서 블록 조작, `/lobby fly`, 접속 시 스폰 이동과 차단 안내 표시를 직접 수행한 검증은 하지 않았다.

## 검증 범위

Paper 서버·월드·블록·생성 엔티티·PluginManager·LuckPerms 권한 계산과 저장소는 실제 구현을 사용했다. CraftPlayer·명령 발신자·인벤토리 화면 객체는 테스트 대역이다. 합성 플레이어는 실제 접속자 목록에 포함되지 않으므로 관리 재점검은 주기 작업이 사용하는 실제 컨트롤러 메서드를 직접 호출했다. 따라서 실제 Minecraft 클라이언트 접속, 로그인 때의 LuckPerms 주입, 화면에서의 상자 아이템 이동, 실제 비행 조작·이동 패킷, 다른 운영 플러그인과의 상호작용은 별도로 확인해야 한다.

격리 검증과 운영 적용은 위에서 구분했다. 임시 서버 파일, 배포 영수증과 로그는 Git에서 제외한 `.runtime/`에만 보관했다.

## 1.0.3 릴리즈와 운영 적용

2026-10-03 KST에 [v1.0.3 릴리즈](https://github.com/underconnor/overworld_lobby/releases/tag/v1.0.3)를 게시했다. 당시 단위 테스트 254개와 실제 Paper 첫 기동 431개·재시작 19개 항목이 통과했다. [Build](https://github.com/underconnor/overworld_lobby/actions/runs/37120912921)와 [Release](https://github.com/underconnor/overworld_lobby/actions/runs/37121006941)가 성공했고, 다운로드 JAR·최종 Paper 검증 JAR·설치 JAR의 SHA-256은 `6ef7b8218b1c87d426f45715beb55adbe1c2440f08ada18914a8119968fee360`으로 일치했다. 당시 전체 우회 사용자의 음식·낙하 피해 허용은 1.0.4에서 위와 같이 변경했다.

기존 설정·Multiverse 파일을 그대로 포함한 번들로 로비만 저장·정상 종료·콜드 백업·재시작했다. 백업은 217,588,009바이트이며 gzip 무결성과 필요한 파일 포함 여부를 확인했다. 백업 SHA-256은 `a46806f9e9ab7ec0140ab6b3929621379ce734984c2c23439d31c71d70d0fa2e`이다. 월드 식별·컨테이너 이미지와 마운트·다른 컨테이너·Compose·접속 정책·OP·화이트리스트·기존 플러그인 JAR·LuckPerms 설정이 유지됐다. 로비 플러그인 7개와 서비스 7개가 정상이며 기동·이벤트 예외가 없었다.

배포 뒤 실제 운영 콘솔에서 `/lobby time noon lobby`, `/lobby weather clear lobby`와 `/lobby reload`를 실행했다. 각 명령이 성공했고 파일 저장·재적용·파일 소유자와 권한 보존을 포함한 12개 점검이 통과했다. 로비의 기존 6000틱·맑음 값은 유지했으며, 이미 저장돼 있던 다른 월드의 18000틱 예외와 모든 개인 보호·스폰 설정도 유지했다. 현재 운영 설정에는 이 월드별 예외가 있으므로 최초 설치 번들의 설정 해시와는 다르다.

운영 상태 응답은 `OverworldLobby 1.0.3 online=2 op=2 permission-bypass=2 effective-bypass=2 creative=2 survival=0`이었다. 자동 재시작 후 두 실제 접속자의 OP·우회·크리에이티브 상태가 확인됐다. 운영 스폰 위치의 블록 조회는 해당 청크가 로드되지 않아 판정하지 못했으며, 정확한 목적지 설정과 기존 Multiverse 설정은 보존됐다. 실제 클라이언트 전체 조작 QA와 운영 서버를 다시 재시작한 뒤 저장 유지 검사는 수행하지 않았다. 전체 재시작 저장 유지는 위 격리 Paper에서 검증했다.
