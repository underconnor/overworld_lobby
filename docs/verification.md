플러그인 활성화·비활성화 오류나 이벤트 처리 예외가 없었다. 확인 항목에는 명령어 실행 및 재적용 성공 여부도 포함되어 있으므로 206개의 서로 다른 사용자 기능을 의미하지는 않는다.

실제 Paper의 PluginManager에 이벤트를 전달해 다음 결과를 확인했다.

- 일반 사용자의 블록 파괴·설치, 문·화로 사용, 양동이, 엔티티 조작·공격, 낙하·화염·익사 피해, PvP, 음식 감소와 피로도 증가를 차단한다.
- 상자 우클릭과 상자 인벤토리 열기는 허용한다. 상자를 누르면서 들고 있는 물 양동이 사용은 별도로 차단한다.
- 자연 생성·스포너 생성 이벤트를 차단한다. Paper의 실제 `spawnEntity(..., NATURAL)` 호출로 생성한 엔티티도 월드에 추가되지 않는다. `CUSTOM` 생성은 허용한다.
- 물 흐름, 성장, 피스톤, 폭발을 차단하고 레드스톤 출력을 유지한다.
- 기본 시간을 6000으로, 날씨를 맑음으로 고정한다. 설정 재적용으로 18000·천둥을 적용하며, 잘못된 설정은 기존 동작을 유지한다.
- 설정 비활성화 시 블록 보호를 해제하고 기존 시간 진행·날씨 진행·자연 스폰 게임 규칙을 복원한다. 월드 목록에 따른 적용 범위도 검사했다.
- 시간이 이미 고정된 네더·엔드에서도 플러그인이 활성 상태를 유지하고 블록 보호와 자연 스폰 차단을 적용한다.
- `/lobby fly on`은 서바이벌에서 비행 허용과 비행 상태를 켠다. `off`는 비행을 끄며, 비행이 꺼진 상태의 비행 시작 이벤트를 차단한다.
- 플레이어 관리 시 음식 20·포만감 20·피로도 0을 적용한다. 배고픔 우회 권한이나 `players.keep-food-full: false` 적용 시 기존 수치를 복원하며, 다시 활성화하면 가득 채운다.

## 정확한 스폰과 자동 이동

`/spawn` 목적지가 `x=-4.5, y=63.5, z=-1.5, yaw=180, pitch=0`과 정확히 일치한다. 소수점 위치를 유지하며 명령 실행으로 기존 정수 단위 월드 스폰을 수정하지 않는다. 서버 재시작 후에도 같은 목적지를 확인했다.

- 기본 `/spawn` 권한을 확인하고, LuckPerms에서 해당 권한을 명시적으로 거부하면 이동하지 않는 것을 검사했다.
- 실제 PluginManager에 `PlayerJoinEvent`를 전달한 뒤 다음 틱의 이동을 확인했다. 접속 이벤트 이후 새로 부여한 자동 이동 우회 권한도 지연 작업이 다시 확인한다.
- `PlayerRespawnEvent`의 목적지와 공허 아래로 내려가는 `PlayerMoveEvent`의 이동 목적지가 정확한 스폰으로 변경된다. 공허 복구는 누적 낙하 거리를 0으로 초기화한다.
- `overworld.lobby.bypass.spawn`은 자동 접속 이동·리스폰·공허 복구를 해제한다. 행동 제한 전체 우회 권한과 OP 기본 권한은 자동 이동을 해제하지 않는다. 자동 이동 우회 권한이 있어도 명시적인 `/spawn` 요청은 허용한다.
- 접속·리스폰·공허 복구 설정을 각각 끌 수 있다. 보호 범위 밖의 출발 월드에는 자동 이동을 적용하지 않으며, 직접 `/spawn`을 실행하면 보호된 목적지로 돌아올 수 있다.
- 설정에 지정한 목적지 월드를 찾을 수 없으면 이동하지 않는다. 명시적으로 지정한 로드된 월드와 빈 월드 설정의 기본 선택도 검사했다.

## LuckPerms 권한 검사

실제로 로드된 LuckPerms의 사용자 데이터와 `LuckPermsPermissible`을 사용했다. 테스트용 CraftPlayer의 네이티브 권한 필드에도 해당 객체를 연결하고 `hasPermission` 호출을 전달하여 플러그인의 일반 권한 검사와 접속 이벤트의 LuckPerms 컨텍스트 처리를 확인했다.

- 권한 없는 사용자 차단, `bypass.block-break` 및 `bypass.interact`의 동작별 허용, 행동 제한 전체 `overworld.lobby.bypass` 허용을 검사했다.
- PvP·상자·배고픔에 대한 개별 우회도 확인했다. 개별 PvP 권한은 낙하 피해 보호를 해제하지 않는다.
- 권한을 회수하면 플러그인 설정 재적용 없이 다음 이벤트부터 차단한다.
- 플레이어 전체 우회 권한이 있어도 행위자 없는 월드 변화 차단은 환경 설정을 따른다.
- LuckPerms 권한을 저장한 뒤 서버 재시작을 거쳐 블록 파괴 권한이 유지되고, 문 차단과 상자 허용은 계속 적용된다.

OP 상태를 LuckPerms Bukkit의 실제 권한 컨텍스트에 반영해 기본 우회 권한도 검사했다. OP은 별도 노드 없이 블록 파괴·설치, 문·양동이·엔티티 조작, 엔티티 공격과 PvP를 허용한다. LuckPerms에서 `overworld.lobby.bypass=false`를 명시하면 OP의 기본 허용보다 우선하며, OP을 해제해도 다음 이벤트부터 보호가 다시 적용된다.

OP과 행동 제한 전체 우회 권한은 음식·피로도 보호와 환경 피해 면역을 유지한다. OP은 서바이벌·비행 설정, 정확한 접속·리스폰 스폰과 공허 복구도 유지한다. 음식 보호와 피해 면역은 각각 `overworld.lobby.bypass.hunger`, `overworld.lobby.bypass.player-damage` 명시 권한으로 해제할 수 있다.

## 차단 안내와 설정 재적용

- 차단된 블록 파괴에는 빨간색 `여기서는 블록을 부술 수 없습니다.`를, 문 사용에는 `여기서는 이 블록을 사용할 수 없습니다.`를 표시한다. `[로비]` 표시는 없다.
- 같은 플레이어가 연속으로 다른 행동을 시도해도 안내 횟수를 제한한다. 안내가 생략되는 동안에도 실제 행동은 계속 차단된다. 기본 간격은 1000ms이다.
- 허용된 상자 열기, 개별 우회 권한 및 OP으로 허용된 행동에는 차단 안내가 없다. 상자를 열면서 들고 있는 양동이 사용이 제한되더라도 상자 접근 실패로 안내하지 않는다.
- 음식 유지와 환경 피해 방지는 안내를 보내지 않는다. 안내 전체 끄기, 행동별 빈 문구, 채팅·액션바 선택과 사용자 문구 재적용을 확인했다.
- 잘못된 안내 간격이나 문자열이 아닌 접두어를 재적용하면 기존 안내 문구·블록 보호·시간·플레이어 설정을 유지한다. 안내 설정 실패로 다른 설정이 일부만 적용되지 않는다.

[Build](https://github.com/underconnor/overworld_lobby/actions/runs/37111103979)와 [Release](https://github.com/underconnor/overworld_lobby/actions/runs/37111268389) 작업이 성공했으며, 내려받은 릴리즈 JAR가 당시 실제 Paper 검증 파일의 SHA-256 `60b92fd2c4ef4831f652afb1b65e1cdcfe08a9b70aa2129eb729805b88eabcda`와 일치했다.

초기 운영 적용은 로비에만 수행했다. 서버 종료 후 214,361,824바이트 백업을 만들고 gzip 무결성과 필요한 파일 포함 여부를 검사했다. 백업 SHA-256은 `8c2220ab9cc9ce2d76307f4d704ea15d32f2477e2c96d255ca49814ab293d7b4`이다.

릴리즈 JAR, OverworldLobby 설정, Multiverse 스폰 값만 적용했다. 운영 설정의 목적지 월드는 `lobby`이고 스폰은 `-4.5, 63.5, -1.5`, 시선은 `180, 0`이다. 접속·리스폰 이동과 공허 복구를 켰다.

별도의 읽기 전용 재점검에서 다음 결과를 확인했다.

- OverworldLobby 1.0.0과 LuckPerms·Multiverse-Core를 포함한 로비 플러그인 7개가 로드됐으며 점검 대상 서비스 7개가 정상 상태였다.
- 설치한 JAR·설정·Multiverse 설정의 해시와 정확한 스폰이 일치했다. 실제 월드 시간은 6000틱이며 자연 스폰·시간 진행·날씨 진행 게임 규칙이 꺼져 있었다.
- 기존 월드 식별 파일 26개, 컨테이너 이미지·마운트·Compose 구성, 접속 정책·OP·화이트리스트, 기존 플러그인 JAR와 로비 외 컨테이너 7개의 상태가 유지됐다.
- 호환성·이벤트·작업 예외와 플러그인 비활성화가 없었다.

이 절은 초기 1.0.0 적용 기록이다. 이후 OP 우회와 차단 안내 변경은 위의 1.0.1 검증 결과를 따른다. 실제 Minecraft 클라이언트 조작을 통한 운영 기능 검증은 수행하지 않았다.

## 검증 범위

Paper 서버·월드·블록·생성 엔티티·PluginManager·LuckPerms 권한 계산과 저장소는 실제 구현을 사용했다. CraftPlayer와 인벤토리 화면 객체는 테스트 대역이다. 따라서 실제 Minecraft 클라이언트 접속, 로그인 때의 LuckPerms 주입, 화면에서의 상자 아이템 이동, 실제 비행 조작·이동 패킷, 다른 운영 플러그인과의 상호작용은 별도로 확인해야 한다.

격리 검증과 운영 적용은 위에서 구분했다. 임시 서버 파일, 배포 영수증과 로그는 Git에서 제외한 `.runtime/`에만 보관했다.
